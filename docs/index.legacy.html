Concepts

Kits

Kits are full app foundations (Ignite, Nexus, etc.). They’re designed to be cloned via the CLI so you start from a real, production-grade structure.

Templates & add-ons

Templates are reusable screens/components. Add-ons are drop-in modules (Auth, Payments, etc.) that can be scaffolded into your codebase while preserving structure.

Workflow

# 1) Create / prepare your app folder
embit init my_app

# 2) Clone a kit from the marketplace into it
embit clone ignite --into my_app

# 3) Scaffold features (repeat forever)
embit feature auth --with bloc --with tests

# 4) Learn and discover
embit help

Best practices

  • Use the CLI for all features so the structure stays consistent across teammates.
  • Prefer kits + add-ons over copy/paste to avoid drift and missing wiring.
  • Commit after each generated feature to keep diffs small and reviewable.

Commands

embit init

Creates a new app workspace with Embit-ready defaults.

embit init my_app
embit init my_app --org com.example --platforms android,ios,web

embit clone

Clones a kit/template into a project (from your marketplace catalog).

embit clone ignite --into my_app
embit clone nexus --into my_app
embit clone template:dashboard --into my_app

embit feature

Scaffolds a new feature module with your chosen patterns and optional wiring.

embit feature home
embit feature auth --with bloc --with tests
embit feature payments --with templates

embit help

Shows command help and examples.

embit help
embit help clone
embit help feature

Feature scaffolding

Feature scaffolding is the fastest way to stay consistent. A single command can create the full folder layout (data/domain/presentation, or your preferred structure), plus wiring and boilerplate. 

# Example: generate an "auth" feature with BLoC and tests
embit feature auth --with bloc --with tests
